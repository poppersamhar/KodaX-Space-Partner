# Partner 插件库（P1–P3）— 人工测试指导

## 功能概述

功能：F146 Partner Plugin Library Extension。规划版本：v0.1.61（fork）；当前宿主仍为 0.1.45，SDK 仍为 0.7.95。测试日期：2026-08-31；测试人员：待填写。

本指南覆盖独立插件包、专家、专家编辑与可选单个 Skill。P4/P5 的真实 MCP 文档连接、授权及写入审核尚需确定首个服务，不能用本指南的通过结果声称已支持第三方读写。

## 测试环境

- 使用本仓库最新构建的 **Electron 桌面应用**，不以浏览器 5174 预览替代。
- 先执行 `npm run build:smoke` 和 `npm run build:partner-extension`；独立包位于 `out/extensions/kodax.partner-library-0.3.0.space-extension`。
- 使用专门的测试项目和隔离 profile；不要卸载或改动其他 profile 中的真实扩展，不删除共享 Skill。
- 安装和专家编辑不需要账号。实际模型回复测试只使用已授权的测试模型和无敏感信息的任务；离线 mock 回复不作为角色执行证据，实际 SDK profile 的自动化验证见开发计划。
- Skill 正向测试使用现有技能库中一项已确认适用于 Partner 的技能，记录其确切名称。不要把示例名称当成已经安装的技能。
- 分别记录开发态与本机打包态、窗口宽度、明暗主题。其他操作系统未测试时填“未验证”。

## 测试用例

### TC-001：独立包安装、启用和撤下

优先级：高。类型：正向测试。前置条件：测试 profile 未安装该包。

1. 打开“设置 → 扩展”，点击安装，选择上述 `.space-extension` 文件。
2. 检查新安装包未自动启用；启用后切换到 Partner，点击“文件”下面的“插件”。
3. 检查目录包含“专家 / 连接器”，专家列表来自包；连接器尚未实现时不能显示为已连接。
4. 禁用包，再重新启用；然后卸载并重新安装、启用。

预期效果：

- [ ] 只有启用时显示 Partner 插件入口；禁用和卸载关闭相应页面，核心聊天与设置安装入口仍可用。
- [ ] 安装不连接账号、不安装 Skill、不发送消息。重装可以恢复入口。

实际结果：待填写。是否通过：[ ] Pass / [ ] Fail。

### TC-002：选择角色、保存会话与版本隔离

优先级：高。类型：正向测试。前置条件：包已启用；使用测试项目和已授权模型。

1. 在 Partner 输入一段未发送草稿，打开插件库，选择“写作导师”。
2. 返回对话，确认草稿原样保留且输入框显示专家。查看右侧专家详情，再发送两轮简短写作任务。
3. 新建另一会话，确认没有自动继承专家；返回旧会话，关闭并重启 Electron，检查原绑定。
4. 在一轮进行时切换或移除专家；下一轮再次发送。若使用 after-turn 排队消息，在其执行前完成专家切换。

预期效果：

- [ ] 选择不自动发送、不覆盖草稿，角色持续作用于该会话，两个会话互不串角色。
- [ ] 当前轮保持原角色；后续新轮读取已经保存的选择。重启恢复原版本；显式 fork 才继承绑定。

实际结果：待填写。是否通过：[ ] Pass / [ ] Fail。

### TC-003：创建、编辑和软删除自己的专家

优先级：高。类型：正向测试。前置条件：包已启用，已经存在一个绑定预置专家的测试会话。

1. 编辑一个预置专家，修改名称和角色提示词，保存。
2. 检查得到独立用户副本、原预置未被修改；选择用户副本并创建会话。
3. 再次编辑这个副本；检查 revision 增加，已有会话仍保留旧提示词。明确重新选择后才应用新版本。
4. 删除这个用户专家，确认对话框说明历史保留；检查原绑定显示不可用。
5. 创建另一个用户专家，卸载并重装同一插件包，检查该自定义专家仍在，已软删除专家没有复活。

预期效果：

- [ ] 保存不会自动选择或替换会话角色；冲突编辑有明确提示，不用旧表单覆盖新版本。
- [ ] 删除不清除会话历史；卸载不删除自定义专家数据、共享 Skill 或原项目文件。

实际结果：待填写。是否通过：[ ] Pass / [ ] Fail。

### TC-004：可选 Skill、失败提示与明确降级

优先级：高。类型：负向测试。前置条件：准备一个兼容现有 Skill 的专家，以及一个填了不存在 Skill 名称的专家。

1. 使用兼容专家连续发送两轮；本轮从原 Skill 入口显式选择另一技能，检查该轮以用户明确选择为准。
2. 使用缺失 Skill 的专家并尝试发送，确认不会伪装成技能已执行，不会自动安装或找替代。
3. 明确选择“仅用提示词”，再次使用；检查偏好在会话中保存、Skill 配置本身没有被删除。
4. 对普通未配置 Skill 的专家使用原有 Skill 入口；切回 Coder 检查原入口和原规则。

预期效果：

- [ ] 缺失、fork 或被既有 hook 规则阻止的配置明确拒绝，不调用外部模型假装成功。动态上下文命令仍禁止；当前 SDK 若返回禁用占位后继续，则保留该原有行为，不把它记成动态命令成功执行。
- [ ] 只有用户明确选择后才跳过专家默认 Skill；原独立 Skill 调用仍可使用，一轮不叠加两个显式 Skill。

实际结果：待填写。是否通过：[ ] Pass / [ ] Fail。

### TC-005：表单和存储边界

优先级：中。类型：边界测试。前置条件：打开创建专家表单。

1. 尝试空名称、全空白提示词；再分别填写 80 字名称、280 字说明、8000 字提示词。
2. 尝试超过上述限制、超过 4 条示例任务或单条超过 512 字；试填 `../skill` 作为 Skill 名称。
3. 保存带中文、换行和 emoji 的合法内容，再打开编辑确认完整保留。
4. 在隔离自动化夹具中验证 128 条用户记录（含软删除记录）和 1MiB 文件上限，不用真实数据手工填满。

预期效果：

- [ ] 合法边界可保存；越界、非法身份和 Skill 名称被拒绝，既有文件保持可读，没有静默截断或覆盖。

实际结果：待填写。是否通过：[ ] Pass / [ ] Fail。

### TC-006：页面和键盘操作

优先级：中。类型：UI 测试。前置条件：包已启用，分别使用宽、窄窗口和明暗主题。

1. 检查 Partner 输入框已没有原八个常驻模板按钮；保留原 Skill、权限、交付格式、模型和项目选择能力。
2. 在插件库用 Tab 切换分类、专家卡片、创建/编辑按钮及表单；保存、取消和错误提示可见。
3. 打开专家详情，查看角色、来源、revision、示例任务和可选 Skill；检查右侧详情仍可关闭再打开。

预期效果：

- [ ] 控件不溢出、长提示词可滚动、焦点可见；选择角色后能继续输入，错误不会变成空白页面。
- [ ] Coder 不显示 Partner 插件导航；现有资料 / 待审核 / 成果卡片保持可用。

实际结果：待填写。是否通过：[ ] Pass / [ ] Fail。

### TC-007：快速切换与并发编辑

优先级：中。类型：性能测试。前置条件：至少两个测试项目和两段 Partner 会话。

1. 连续切换会话、打开/关闭插件页面 20 次，同时保留未发送草稿。
2. 在保存或选择未完成时切换项目，再返回；同时从两份旧表单编辑同一用户专家。
3. 记录首次加载与保存耗时，观察是否卡死、出现重复请求或持续增长的后台刷新。
4. 尚未发送的草稿已选专家时，分别通过侧栏、文件菜单、快捷键、命令面板和项目行新建对话；检查专家清空而正文保留。用自动化夹具延迟旧创建 ACK，确认旧会话不能重新激活。

预期效果：

- [ ] 旧请求不会改变新项目的专家或吞掉草稿；并发同 revision 修改至多一份成功，另一份明确冲突。
- [ ] 操作中有反馈、关闭后不会持续调用；记录实际耗时，不把未测量结果写成性能保证。

实际结果：待填写。是否通过：[ ] Pass / [ ] Fail。

### TC-008：不可信扩展边界

优先级：高。类型：安全测试。前置条件：仅用隔离 profile 和仓库恶意包自动化夹具。

1. 尝试安装包含越界路径、符号链接、可执行入口、超大压缩数据、错误 hash 或不兼容 API 的包。
2. 在专家名称/说明填入 `<img src=x onerror=alert(1)>`，查看列表和详情。
3. 运行 IPC/frame 来源负向测试：伪造 source/token、子 frame 发宿主 IPC、重复请求、禁用后的新请求。
4. 检查插件页面只得到公开定义和受限结果，没有 Node、任意文件、账号密钥或任意 invoke。

预期效果：

- [ ] 不可信包/调用被拒绝，已有有效包和主应用仍可用；HTML 显示为文本，不执行脚本。
- [ ] 完整性 hash 只证明内容一致，界面不把它当作发布者身份认证。

实际结果：待填写。是否通过：[ ] Pass / [ ] Fail。
