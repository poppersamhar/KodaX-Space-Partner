## 1. 需求概述

### 已确认的产品边界

- Partner 左侧“新对话 / 文件”下面增加“插件”，库内只有“专家”和“连接器”两个分类。
- 专家是角色名称、用途说明、场景提示词和创建者可选配置的 Skill 的产品化组合，不是新的 Agent 执行引擎。
- Skill 仍是 Coder / Partner 共用的能力。保留现有技能库、入口、发现、调用和权限逻辑；不增加技能分类、安装器、自动匹配、推荐、替代或“Skill 引用解析”宿主服务。
- 专家没有配置 Skill 时，只增加专家提示词，不额外处理 Skill；这不关闭 Space 原有的独立 Skill 能力。
- 一段 Partner 会话最多一个专家，可选择多个连接器。专家对后续每轮对话生效，不是只给第一条草稿填入模板。
- 连接器通过 MCP 接入第三方系统；账号连接、当前会话选择、文档范围和写入授权是不同状态。
- 输入框展示当前专家和连接器；现有“资料 / 待审核 / 成果”卡片及右侧详情区继续承载文档使用和交付。
- 插件库整体必须位于可独立安装、禁用和卸载的 Space Extension 包，不能仅成为带开关的内置页面。

### 本轮计划采用的最小范围

- 第一版允许专家配置零或一个明确的现有 Skill。当前显式调用会拒绝同条消息中的多个 Skill；不为本功能改写该共享规则。多 Skill 组合不作为本期已解决能力。
- 第一包由本项目提供，携带前端资源和专家 / 连接器声明；不开放插件市场、任意主进程代码、安装脚本或 SDK filesystem hooks。
- 先贯通一个纯提示词专家，再迁移现有八个场景预设、添加专家编辑和可选 Skill 配置，随后接入连接器读写。
- 远端第一期支持能力已确认的文档读取、新建和受审修改；删除文档、改变共享权限、群发、后台自动同步不在本期范围。
- 不改 Coder 布局、运行时所有权、共享 Skill 机制、模型选择和现有权限底线。

### 预计新增区域

- Extension 独立源码 / 构建产物目录，包含 manifest、ui、experts、connectors；具体目录名在 spec 固定。

## 3. 技术方案

### A. 可独立投放的包与最小宿主

- 包内包含版本化 manifest、预编译 UI 静态资源、专家提示词、连接器声明和普通资源，不含 main / preload 入口、安装脚本或 Skill 安装内容。
- UI 在隔离的浏览器 frame 内运行，通过有限、版本化的消息桥请求宿主；不与可信主 renderer 同源加载任意模块，不获得 Node、完整 IPC、账号 token 或任意文件权限。
- 扩展资源限制在经验证的包根目录，校验大小、入口、路径穿越、符号链接、资源完整性和兼容版本。完整性 hash 不能被描述为发布者身份认证。
- 安装只校验并登记，不自动连接第三方服务。启用后才挂载导航 / 页面 / 声明；所有注册和请求都带扩展归属并由主进程校验。
- 新增宿主自有“设置 → 扩展”管理入口。即使插件库卸载，该入口仍能重新安装包。
- 独立前端加载只是 UI 宿主，不新增 Agent 执行引擎，不开启 SDK 任意代码扩展总开关。
- 声明可组合已支持的连接器工具；新原生适配能力不能仅靠 manifest 伪装成已经支持，需另行增加受审适配或使用实际具备该能力的 MCP 服务。

### B. 专家、草稿与会话

- 选择专家先绑定当前 Partner 草稿，不覆盖草稿、不自动发送、不隐式新开或清空已有会话。
- 首次发送时，主进程按已启用包中的专家 ID / 版本解析配置并持久化；前端不直接提交权威系统提示词。
- 每轮执行读取会话配置，组合“Partner 基础 profile + 专家配置”，保留基础验证与权限。读取历史、重启和上下文压缩后仍能恢复该绑定。
- 专家更改 / 移除在下一轮生效并可见；运行中的一轮固定其配置。新建其他会话不自动继承；显式 fork 按原会话继承配置。
- “下一轮”按实际开始执行划分：after-turn 排队消息在新一轮开始时读取已成功保存的专家；仍由 SDK 在当前轮消化的 interrupt 消息保持当前角色。保存尚未完成时不能提前让新配置生效。
- 修改专家定义产生新版本，不悄悄修改旧会话角色。旧会话缺少扩展或专家时显示不可用状态，不静默使用已经卸载的提示词。
- 专家编辑只管理名称、说明、提示词、示例任务及可选的一个明确 Skill 配置。预置专家编辑为用户副本，不修改共享 Skill 或已安装包的只读资源。
- 配置 Skill 后沿用既有调用准备和拒绝规则；缺失、项目不可用或权限不支持时明确提示，不搜索替代、不自动安装。用户仍可独立使用原 Skill 入口。
- 现有 SDK 的动态上下文在 Partner 中禁止执行命令；它可能将正文替换成“host 禁用”占位后继续模型回合。本插件保留此语义，不新增整轮拒绝规则，也不能把占位当成动态命令已执行。hook/fork 等继续各自现有拒绝路径。
- 专家默认配置与用户本轮显式 Skill 选择冲突时，以用户显式选择为准，该轮不叠加第二个 Skill；下一轮恢复专家默认配置。缺失 Skill 的降级需用户明确选择仅按角色继续，不能显示为技能已成功执行。

### C. 连接器与远端文档

- 分开保存连接器声明、账号连接状态、会话绑定和文档范围。账号已连接不会给其他会话授权全部知识库。
- 从当前会话发起连接，完成账号授权和范围确认后添加输入框标签。移除标签仅解绑本会话；断开账号和卸载扩展是独立操作。
- 凭据使用宿主保管的引用，不能进入插件 UI、提示词、普通配置、日志和成果；SDK 原有全局 / 项目 MCP 配置不能被插件安装隐式覆盖。
- 模型只能看见本会话允许的连接器工具；实际调用也必须校验同一权限，不以提示词、UI 状态或 MCP 工具自报只读作为授权。
- 读取的文档带来源、明确文档身份、获取时间和可用版本信息，显示在“资料”；文档内容是证据，不是角色指令或授权。
- 写入按“生成方案 → 待审核 → 用户确认 → 后端提交 → 成果回执”执行；只有后端真实提交成功才能显示已写入。
- 远端提案绑定账号 / 会话 / 扩展、目标文档、操作、具体内容 hash 和可用基础版本。确认只覆盖该提案，执行时重验授权、包状态与目标，不允许模型代替用户确认。
- 重复提交、权限撤销、版本冲突、超时及结果不确定有明确状态；能力不支持时不承诺版本锁、自动回滚或盲目重试。
- 账号断开后立即禁止新的远端调用。已保存引用和结果只按现有访问 / 留存策略展示，不因界面开关隐式删除或重新授权。

### 与既有规划的关系

这是当前 fork 的明确新增 F146，不将 F096 的未来连接器规划或 F102 的通用 slot registry 标记为已经实现。F146 复用 F096 关于账号、范围、来源、撤销的约束；插件入口和受审远端写入采用本次用户确认的新产品边界。只补本库实际需要的挂载点，不重启完整通用插件平台规划。F137 / F139 的既有范围和实现状态不变。

## 4. 接口契约

以下是已确认的五组职责；各阶段通过契约测试逐步交付，不将后续未实现能力当成已有 API：

| 接口组       | 最小职责和边界                                                                                                              |
| ------------ | --------------------------------------------------------------------------------------------------------------------------- |
| 扩展生命周期 | 安装、列出、启用、禁用、卸载；manifest / 宿主协议兼容；所有能力按 extensionId 归属                                          |
| UI 挂载      | Partner 左侧入口、插件库视图、输入框标签和现有右侧详情；固定消息类型，不提供任意 invoke 或任意系统路径                      |
| 会话配置     | 获取 / 更新 / 订阅专家和连接器绑定；草稿转会话、配置版本、每轮快照、恢复 / fork / 删除；Coder 不接收 Partner 绑定           |
| 连接与调用   | 授权状态、凭据引用、连接 / 断开、会话选择和工具范围；本轮飞书使用官方 CLI 适配，既有 MCP transport 不变，主进程执行权限检查 |
| 文档与审核   | 资料引用、远端修改提案、人工批准 / 拒绝、执行与回执；复用三卡片和详情展示，区分本地文件与远端资源                           |

最低数据约束：

- ExpertDefinition：稳定 ID、extensionId、revision、名称、说明、prompt、可选 skillRef、示例任务。没有 skillRef 时不增加专家专用 Skill 操作。
- SessionBinding：sessionId / surface / project identity、revision、可选 expertRef、显式 connectorBindings；不包含密钥；后端按实际账号授权和包状态收窄能力。
- RemoteProposal：operationId、extensionId、sessionId、connectionRef、resourceRef、create / update、不可变内容摘要 / hash、可用 baseVersion、审核与执行状态。
- Bridge 请求必须校验实际 frame / 包 / 会话归属、允许操作、有效长度和当前权限；不能信任消息正文自报的身份。返回值和日志统一脱敏。

## 5. 实现步骤

用户已确认按以下顺序开发。P1–P6 同时作为实现票号，后续票依赖前一票的接口；同一票的独立前后端适配可并行，验收不以界面文字替代实际运行。正式 seam 与本地验证记录见下。

| 阶段              | 可交付闭环                                                                                        | 进入下一阶段前的检查                                                                           |
| ----------------- | ------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| P1：真实扩展包    | 单独构建一个最小包；设置中安装、启用后出现“插件”及真实扩展视图；禁用 / 卸载后撤下，宿主可继续使用 | 无包时开发 / 打包 / 启动正常；不向扩展暴露主 frame IPC；停用阻止新请求；卸载后可重新安装       |
| P2：第一个专家    | 包内一个纯提示词专家；选择后输入框显示；连续多轮按该角色执行；重启恢复                            | 检查实际传给 SDK 的 profile，而非只看 UI；两会话不串角色；原草稿、默认 Partner 和 Coder 正常   |
| P3：专家产品化    | 八个预设转为角色与示例任务；支持创建 / 编辑用户专家、零或一个 Skill 配置、下一轮切换 / 移除       | 原八按钮退出常驻输入区；原 Skill 入口与机制不变；显式 Skill 优先；缺失配置和卸载状态不伪装成功 |
| P4：连接器读取    | 飞书官方 CLI 适配；账号验证、范围确认、会话标签、读取文档并在资料 / 详情查看                      | 账号授权与会话授权分离；多账号 / 多会话隔离；解绑、撤权和失败真实展示；不扩大共享 MCP 配置     |
| P5：受审远端写入  | 对已支持连接器提出新建 / 修改方案，审核后提交，成果显示真实文档链接和回执                         | 拒绝不写、只读不写、撤权不写；重复 / 冲突 / 不确定结果测试；不绕过 Partner gate                |
| P6：Electron 验收 | 在真实 Electron 开发态和打包态验证完整闭环及安装 / 卸载 / 重装                                    | 全量自动检查、双轴 code review、人工检查和回归通过；真实第三方验证与测试服务验证分别记录       |

第三方接入的外部前置条件：本轮按用户选择使用飞书官方 CLI，固定并核实其读写 / 授权契约，再由用户完成测试账号授权。CLI 不是 MCP server，不伪装为 MCP 接入。当前未安装和授权真实 CLI，不能标记真实连接器已验证。测试夹具只用于自动化，不能在用户界面冒充已连接第三方服务。

### 实施契约与进度（2026-08-31）

- **P1 代码、自动检查与 macOS arm64 打包态生命周期通过。** `SpaceExtensionStore` 持有归档与启用注册；`.space-extension` ZIP 内含 `manifest.json`、独立 `ui/index.html`，安装/升级默认停用。主应用仅注册 `space.extensions.list/install/setEnabled/uninstall/view`，主进程校验 primary main frame。UI 使用 `app://space/__space-extension-frame` + `sandbox="allow-scripts"` 和独立无网络 CSP，不能使用继承主页面 CSP 的 srcDoc。包在 `extensions/partner-library` 单独构建，主应用构建无需包存在。
- **P2 代码与自动检查通过。** `SpaceExpertRefT={extensionId,expertId,revision}` 是前端可提交的选择；`PartnerExpertSnapshotT={extensionId,extensionVersion,expert}` 只能由宿主解析并持久化。使用 `space.extensions.catalog/resolveExpert` 与 `session.partnerExpert.get/set/changed`，创建接纳在 ACK 前落盘。每轮固定快照并检查当前扩展可用；旧快照保持旧角色，不能代替当前使用授权。临时会话拒绝持久专家绑定，不偷偷把临时会话转为持久会话。

### 原功能验收清单

- [ ] Partner 显示一个“插件”入口，库内恰为“专家 / 连接器”；Coder 不新增此入口，原 Skill 入口和调用不变。
- [ ] 插件 UI 代码及目录来自独立安装包；卸载不是隐藏已静态编译进主 renderer 的页面；无包时 Space 可构建 / 启动 / 正常聊天。
- [ ] 纯提示词专家不触发额外 Skill 搜索、推荐或安装；配置的 Skill 复用旧执行边界，不能绕过单项 / dynamic-context / 工具权限限制。
- [ ] 专家标签、后端绑定和每轮 SDK profile 一致；创建 ACK 前持久化，失败可恢复；重启 / fork / 切换 / 删除覆盖测试。
- [ ] 两个 Partner 会话的专家和连接器不串；Coder 运行配置和技能行为不受影响；已有会话无新字段仍可用。
- [ ] 输入框不再固定展示八个模板按钮；专家 / 连接器选择不覆盖草稿、不自动发送；点击标签用现有右侧看详情。
- [ ] 连接成功、会话启用和写入权限分开；只读、断开、过期、错误有真实状态；移除标签不删除账号配置。
- [ ] 远端资料、待审核改动、成功回执进入对应三卡片；本地提案流程保持可用。
- [ ] 未确认、授权撤销、目标变化、扩展禁用或提案内容变化时不能提交；失败或未知结果不显示成功、不盲目重试。
- [ ] token / secret 不出现在插件 UI、模型输入、普通持久化记录、日志、资料或成果。
- [ ] 安装 / 禁用 / 卸载 / 升级失败不破坏主应用；兼容版本、包路径安全、frame 来源和调用归属有负向测试。
- [ ] 禁用立即阻止新调用；已在途的远端操作先结算 / 对账再完成卸载，不声称能撤回已提交请求。历史会话、成果、审核、自定义专家配置及共享 Skill 保留；旧绑定显示不可用。
- [ ] 重新安装后能恢复可用入口，账号若需重新授权则明确提示；扩展升级不静默改变旧会话专家配置。
- [ ] 真实 Electron 下完成专家多轮、重启、连接器读写审核及卸载 / 重装验收；mock 和真实第三方的测试结论分别记录。
