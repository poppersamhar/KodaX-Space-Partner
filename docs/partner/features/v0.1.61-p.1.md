## FEATURE_PF001: Partner Plugin Library Extension

### 1. 需求概述

在既有 Partner surface 上增加可独立安装、禁用和卸载的插件库。插件库包含专家与连接器：专家为 Partner Profile 叠加角色提示、示例任务和至多一个现有 Skill；连接器通过 Space Electron 可信宿主完成账号授权、会话选择、资源范围校验和受控远端操作。

PF001 必须保持 Partner 是 Space 的一个 surface，而不是新的 Runtime；不得通过修改 Coder 专属提示词、布局或执行逻辑取得能力。

详细产品范围、阶段修订和风险矩阵见[开发计划](v0.1.61-partner-plugin-library.md)。

### 2. 影响范围

- Partner 插件包：`extensions/partner-library/**`
- Partner UI：`apps/desktop/renderer/src/features/partner/**`
- 专家与连接器 UI：`apps/desktop/renderer/src/features/extensions/**`
- 可信连接器宿主：`apps/desktop/electron/partner-connectors/**`
- Partner Runtime 适配：`apps/desktop/electron/kodax/partner-*`
- 共享接缝：Space Extension host、IPC schema、Electron main、Shell、资源与打包脚本
- Partner 文档：`docs/partner/**`

代码继续位于各自的 Electron、Renderer、Extension 和共享契约层；本次文档迁移不改变源码模块路径或运行数据位置。

### 3. 技术方案

1. Extension 包声明专家、连接器、受限 UI 和所需宿主能力，不装载任意主进程代码。
2. 一段 Partner 会话最多绑定一个专家，并可选择多个连接器；运行中的一轮使用不可变快照。
3. OAuth、CLI、凭据、账号选择、资源范围、写入审核和真实远端调用由 Electron 主进程可信宿主拥有。
4. 连接器以 provider-specific adapter 接入，共享 catalog、session binding、provenance、revocation 和结果状态。
5. 平台原生交付使用 provider-neutral 的 verified canonical URL 与单次打开信号；失败、`unknown` 或 `partial` 不冒充成功。
6. Partner 任务资料、协作和产物进入统一 typed detail workspace；Coder 不消费 Partner 专属能力。

### 4. 接口契约

- Extension ID 保持 `kodax.partner-library`。
- Host API 通过 `hostApiVersion` 与 `requiredHostCapabilities` 协商；版本号本身不授予权限。
- 专家、连接器、账号和会话选择使用稳定 ID 与 revision，不从显示名称或模型参数推断授权。
- Renderer 和 Extension UI 只能提出请求；主进程必须在每次真实操作前重新校验账号、连接器 revision、资源 scope 与操作权限。
- 新建与修改的风险路由不同：满足既定低风险契约的新建可直接执行并回读；修改既有资源继续走受审提案。
- 共享 IPC 或 Host contract 的变化必须记录在 [`INTEGRATION.md`](../INTEGRATION.md)，并包含 Coder 回归证据。

### 5. 实现步骤

PF001 沿用已经批准的 P1–P9 tracer-bullet 阶段，不把这些阶段重新登记为独立 PF：

- P1–P3：独立插件包、插件库 UI、专家目录与会话绑定。
- P4–P6：飞书连接器、可信宿主、远端快照、审核链与真实服务验收。
- P7：首个正式平台专家与受控任务。
- P8：provider-neutral 平台原生资源直达交付。
- P9：统一任务详情工作区和 receipt-first 资源呈现。

票序、完成证据与仍未完成的人工作业以[详细开发计划](v0.1.61-partner-plugin-library.md)和[测试指南](../test-guides/FEATURE_146_v0.1.61_TEST_GUIDE.md)为准。

### 6. 验收标准

- 插件包可以安装、启用、禁用、卸载，并且不破坏核心 Partner 对话。
- 专家选择不覆盖草稿、不自动发送，跨轮次使用正确快照且不串会话。
- 连接器账号连接、会话选择、资源 scope 和写入权限彼此独立。
- 凭据与 CLI profile 不进入 Renderer、插件 UI、模型上下文或普通日志。
- 远端成功必须具有可信资源身份和 canonical URL；未知或部分结果不自动重试、不显示为成功。
- Partner 的本地 Artifact、平台原生资源与受审修改不互相冒充。
- 自动测试、打包验证和真实服务人工验收分别记录。
- 共享 IPC、Shell、Runtime 或主进程改动通过相应 Coder 回归。
- 本 Feature 在 Partner 中完成后先进入 `Ready`；只有真实合入 Space 主线后才能标记 `Integrated`。

当前状态仍为 `InProgress / Local`。P9 自动化与独立评审已通过，但完整 F146 的真实服务与发布门槛尚未全部完成。
